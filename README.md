# Прогноз пассажиропотока московских трамваев

Проект хакатона по прогнозированию числа посадок на трамвайных маршрутах и созданию веб-сервиса для анализа результатов. Backend будет реализован на FastAPI.

## Текущий статус

В репозитории пока находится архив с тестовой частью данных. Полный `train.csv` будет добавлен позже. Приложение, модель и Docker-конфигурация ещё не реализованы.

## Данные

Официальный архив: [Яндекс Диск](https://disk.yandex.ru/d/DiFwlfMOauxjBg).

Ожидаемый состав распакованного датасета:

```text
data/
├── train.csv                     # январь–август 2025, будет добавлен позже
├── test.csv                      # сентябрь–октябрь 2025
├── test_submission.csv           # пример файла решения
├── labels/
│   ├── labels_day_train.csv
│   └── labels_day_test.csv
└── spravochniki/                 # маршруты, остановки и координаты
```

Сырые CSV используют разделитель `;` и кодировку UTF-8. Основной timestamp — `tran_date_time`. Успешная посадка определяется условием `validation_result == 1`, маршрут берётся из `ngpt_route`.

Не храните распакованные многогигабайтные данные в Git. Положите архив в корень проекта и распакуйте его локально:

```bash
mkdir -p data
unzip dataset.zip -d data
```

Если архив скачан под другим именем, укажите его вместо `dataset.zip`.

## Задача моделирования

Нужно спрогнозировать пассажиропоток на период с 1 ноября по 31 декабря 2025 года с почасовой детализацией для маршрутов `1, 5, 7, 11, 12, 17, 25, 26, 28, 50`.

Формат результата:

```text
route;date;hour;prediction
```

Файл должен содержать полную сетку из 14 640 строк: 10 маршрутов × 61 день × 24 часа. Значение `prediction` должно быть неотрицательным. Метрика — WAPE-score:

```text
WAPE       = sum(abs(y - prediction)) / sum(y)
WAPE-score = max(0, 1 - WAPE)
```

## Планируемая архитектура

- FastAPI — REST API и экспорт прогнозов;
- Python ML-контур — подготовка данных, обучение и инференс;
- React + TypeScript — дашборд и карта;
- Docker Compose — локальный запуск и поставка решения.

Остановочная детализация является дополнительной: `place_id` обозначает площадку или депо, а не остановку. Основной прогноз строится на уровне `маршрут × дата × час`.

## Установка и запуск

Команды установки появятся вместе с кодом приложения и файлом зависимостей. До этого момента для подготовки репозитория достаточно:

1. Клонировать репозиторий.
2. Скачать датасет.
3. Распаковать его в `data/`.
4. Добавить `train.csv`, когда организаторы предоставят полную выборку.

## Производительность

Перед сдачей здесь необходимо указать воспроизводимые результаты нагрузочного теста: конфигурацию CPU/RAM, команду запуска, профиль нагрузки, RPS, p95, загрузку CPU и потребление памяти. Целевой режим — сотни RPS при p95 менее 200–300 мс на 2–4 vCPU и 2–4 ГБ RAM без swap.
