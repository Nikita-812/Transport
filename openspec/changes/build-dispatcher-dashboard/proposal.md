## Why

Бекенд уже отдаёт почасовой прогноз посадок по маршрутам, но интерфейс — однофайловая заглушка без карты Москвы, сценарных коэффициентов и представления, полезного диспетчеру. Критерии хакатона оценивают полноту функциональности (горизонты, агрегация, карта, выгрузка), корректирующие коэффициенты в интерфейсе, бизнес-ценность и качество демо. Поэтому нужен полноценный дашборд, собранный поверх существующего API без изменений бекенда.

## What Changes

- Новое приложение React/TypeScript в `frontend/`. Оно собирается в один самодостаточный `static/index.html`, который существующие `forecast_api.py`, Dockerfile и Compose раздают без изменений.
- Исследование прогноза: выбор маршрутов, горизонты «день / месяц / год / период», диапазон часов, детализация, KPI, графики динамики, тепловая карта «день недели × час», таблица и CSV-выгрузка.
- Карта Москвы: линии всех 10 маршрутов окрашены по прогнозной нагрузке, сутки проигрываются по часам, есть режим «Сейчас». На карте остановки с агрегатом «маршруты через остановку».
- Сценарные корректирующие коэффициенты (погода, сезон, события), которые мгновенно пересчитывают все представления и выгрузку.
- Вкладка «Выпуск и расписание»: требуемые рейсы и интервал движения по прогнозу при редактируемых допущениях.
- Вкладка «О модели»: метрики, область определения и адаптации, источники данных со ссылками, ограничения.
- Статическая геометрия путей и остановок из OpenStreetMap, скрипт её обновления и скрипт локального снимка прогноза для разработки.
- Заглушка `static/index.html` заменяется собранным приложением. Контракт API не меняется.

## Capabilities

### New Capabilities

- `dashboard-shell`: поставка через `static/index.html`, доступ к API и понятные ошибки, покрытие и статус снимка, режим «Сейчас» по московскому времени, тема, раскладка и состояние в URL.
- `forecast-exploration`: маршруты, горизонты и интервалы, клиентские агрегации, KPI, графики, таблица, CSV-выгрузка.
- `route-load-map`: карта нагрузки маршрутов, проигрывание суток, остановки и агрегат по остановке.
- `scenario-coefficients`: сценарные коэффициенты и их согласованное применение ко всем представлениям и выгрузке.
- `operations-planning`: оценка требуемых рейсов и интервалов по прогнозу.
- `model-transparency`: сведения о модели и снимке, качество, область применимости, источники и ограничения.

### Modified Capabilities

Нет. Основные specs в `openspec/specs/` отсутствуют. Контракт выдачи прогноза из change `benchmark-models-on-two-devices` используется как есть.

## Impact

- Новые и изменяемые файлы: `frontend/**` (исходники, тесты, скрипты, данные OSM), `static/index.html` (артефакт сборки вместо заглушки), раздел README про интерфейс, `docs/frontend/` (скриншоты).
- Бекенд не меняется: корневые `*.py`, `requirements-*`, `Dockerfile`, `compose.yaml`, `.dockerignore`, Python-тесты. Используются только `/health`, `/forecasts`, `/forecasts/export.csv`, `/forecasts.csv`, `/reference-map`.
- Зависимости появляются только в `frontend/package.json`, для сборки нужен Node 24. Рантайм-контейнер не меняется.
- Браузер обращается к внешнему серверу только за растровыми тайлами подложки, для них есть запасные источники. Геометрия OSM вшита в сборку, Overpass нужен только для её обновления.
- `static/index.html` вырастает примерно с 12 КБ до 2–3 МБ и раздаётся тем же `FileResponse`.
