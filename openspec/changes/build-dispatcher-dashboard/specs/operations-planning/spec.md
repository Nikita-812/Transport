## Purpose

Перевод прогноза посадок в оценку требуемого числа рейсов и интервала движения в пиковый час, чтобы показать применение прогноза для распределения подвижного состава и уточнения расписания.

## ADDED Requirements

### Requirement: Trips and interval estimate
Требуемые рейсы в час SHALL считаться по формуле ⌈B·s / (C·f)⌉, где:
- B — посадки в час по сценарию;
- s — доля посадок часа, одновременно находящихся в вагоне на самом загруженном перегоне;
- C — вместимость вагона;
- f — целевое заполнение.

Интервал SHALL равняться ⌊60 / рейсы⌋ минут. Значения по умолчанию: C = 180, f = 0,7, s = 0,35. При B = 0 SHALL показываться «нет потребности».

#### Scenario: Typical peak hour
- **WHEN** B = 1000 при значениях по умолчанию
- **THEN** требуется 3 рейса в час с интервалом 20 минут

#### Scenario: No demand
- **WHEN** B = 0
- **THEN** показано «нет потребности», деления на ноль нет

### Requirement: Planning view
Вкладка «Выпуск и расписание» SHALL показывать по каждому выбранному маршруту пиковый час выбранного дня (или среднего дня периода), посадки в этот час, требуемые рейсы и интервал. Поля C, f, s SHALL редактироваться с единицами измерения, изменения SHALL сразу пересчитывать таблицу.

#### Scenario: Capacity change
- **WHEN** пользователь меняет вместимость вагона со 180 на 250
- **THEN** рейсы и интервалы пересчитываются сразу

### Requirement: Assumption disclosure
Вкладка SHALL сообщать, что посадки в час не равны наполнению вагона, а параметры s, C и f — допущения, требующие калибровки по обследованиям пассажиропотока.

#### Scenario: Disclosure visible
- **WHEN** пользователь открывает вкладку
- **THEN** пояснение о допущениях видно без дополнительных действий
