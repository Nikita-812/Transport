## Purpose

Перевод прогноза посадок в оценку требуемого числа рейсов и интервала движения по маршрутам и часам, чтобы показать применение прогноза для распределения подвижного состава и уточнения расписания.

## ADDED Requirements

### Requirement: Trips and interval estimate
Для каждого выбранного маршрута и часа дашборд SHALL считать требуемые рейсы в час по формуле ⌈B·s / (C·f)⌉, где:
- B — посадки в час по сценарию;
- s — доля посадок часа, одновременно находящихся в вагоне на самом загруженном перегоне;
- C — вместимость вагона;
- f — целевое заполнение.

Интервал SHALL равняться ⌊60 / рейсы⌋ минут. Значения по умолчанию: C = 180, f = 0,7, s = 0,35. Час с B = 0 SHALL отмечаться «нет потребности». Больше 20 рейсов в час SHALL помечаться как превышение пропускной способности линии.

#### Scenario: Typical peak hour
- **WHEN** B = 1000 при значениях по умолчанию
- **THEN** требуется 3 рейса в час с интервалом 20 минут

#### Scenario: No demand
- **WHEN** B = 0
- **THEN** час отмечен «нет потребности», деления на ноль нет

### Requirement: Planning view
Вкладка «Выпуск и расписание» SHALL показывать:
- таблицу «маршрут × час» для выбранного дня или среднего дня периода с выделенными пиковыми часами;
- сводку максимума рейсов по маршрутам;
- форму допущений с единицами измерения, сохранением и сбросом.

Изменение допущений или сценария SHALL сразу пересчитывать вкладку.

#### Scenario: Capacity change
- **WHEN** пользователь меняет вместимость вагона со 180 на 250
- **THEN** требуемые рейсы и интервалы пересчитываются сразу

### Requirement: Assumption disclosure
Вкладка SHALL сообщать, что посадки в час не равны наполнению вагона, а параметры s, C и f — допущения, требующие калибровки по данным обследований пассажиропотока.

#### Scenario: Disclosure visible
- **WHEN** пользователь открывает вкладку
- **THEN** пояснение о допущениях видно без дополнительных действий
