# Пак промптов: дашборд диспетчера

## Как пользоваться

1. Разделы идут строго по порядку. На каждый раздел — новый чат (Codex или Claude Code), в него вставляется промпт этого раздела целиком. Вся работа — в ветке `feat/frontend-dashboard`.
2. После раздела полезно запустить «Промпт ревью» в другом агенте (Codex ↔ Claude Code): свежий взгляд ловит отступления от спеки.
3. Если сессия прервалась — «Промпт продолжения». Если агент упёрся в правку бекенда или недоступную сеть, он записывает это в `handoff.md` и останавливается. Решение принимает команда.
4. Единственный источник правды — файлы change. Если в обсуждении что-то поменялось, сначала правим design, specs или tasks, потом запускаем агента.

**Кому что отдать.** Это рекомендация, не правило. Opus 5.5 — Claude Code, GPT-6 Astra — Codex.

| Раздел | Кому | Уровень рассуждений | Что важно |
|---|---|---|---|
| 1. Каркас и сборка | Opus 5.5 | high | сеть для npm и проверка страницы в браузере |
| 2. Фильтры и агрегации | Astra | xhigh | часовые пояса, границы месяцев, согласованность с API — всё проверяется тестами |
| 3. Графики, таблица, CSV | Opus 5.5 | high | визуальная проверка в обеих темах |
| 4. Геометрия OSM | Opus 5.5 | xhigh | сеть для Overpass, склейка путей и кластеризация |
| 5. Карта | Opus 5.5 | xhigh | самый рискованный раздел, отладка по картинке |
| 6. Сценарии | Astra | high | доменная логика, хорошо покрывается тестами |
| 7. Выпуск и «О модели» | Astra | high | формулы и тексты строго по design |
| 8. Полировка и приёмка | Opus 5.5 | high | браузер, Docker, скриншоты |

Ревью делает другой агент на уровне high, для раздела 5 — xhigh. Уровень max включайте, только если агент дважды не смог починить одну и ту же ошибку. low и medium подходят для промпта продолжения с мелкими хвостами.

Разделам Astra (2, 6, 7) сеть не нужна: все пакеты ставятся в разделе 1. Если у Codex нет браузера, визуальные проверки его разделов доберёт ревью в Opus.

**Общий блок правил** уже встроен в каждый промпт ниже, отдельно его вставлять не нужно.

## Раздел 1. Каркас, сборка и доступ к API

```text
Ты работаешь в репозитории хакатонного проекта «Прогноз пассажиропотока московских трамваев» (FastAPI-бекенд + ML). Ветка: feat/frontend-dashboard (переключись на неё, если ты не в ней).

Спецификация фронтенда — OpenSpec change openspec/changes/build-dispatcher-dashboard/. Прежде чем что-то делать, целиком прочитай proposal.md, design.md, все specs/*/spec.md, tasks.md и handoff.md.

ЗАДАЧА: выполни раздел 1 tasks.md «Каркас, сборка в static/index.html и доступ к API» — только его, ничего из следующих разделов. Если у тебя есть скилл openspec-apply-change, можешь использовать его для этого change, но в пределах раздела 1.

ОБЩИЕ ПРАВИЛА
1. Разделы строго по порядку. Если предыдущие разделы в tasks.md не отмечены — остановись и сообщи.
2. Бекенд не трогать: корневые *.py, requirements-*, Dockerfile, compose.yaml, .dockerignore, Python-тесты. static/index.html меняется только через `npm run build`. Не коммитить data/, dataset/, artifacts/, node_modules/, dist/.
3. Решения design.md не менять молча: любое отклонение — с причиной в handoff.md. Если требование невыполнимо без правки бекенда — запиши это в handoff.md и остановись на этом пункте.
4. Интерфейс на русском, числа в формате ru-RU. Никаких выдуманных данных (метрик, прогнозов по остановкам).
5. Бекенд для проверки (из корня репозитория):
   FORECAST_DIR=artifacts/service .venv/Scripts/python.exe -m uvicorn forecast_api:app --port 8000
   На Windows в PowerShell: $env:FORECAST_DIR='artifacts/service'. Если artifacts/service пуст — сначала frontend/scripts/dev_snapshot.py (design D3, там же обход, если data/processed не читается).
6. Перед завершением должны быть зелёными:
   - в frontend/: npm run typecheck, npm run lint, npm test, npm run build;
   - в корне: .venv/Scripts/python.exe -m unittest discover.
   Затем проверь сценарии раздела в браузере на странице, которую отдаёт бекенд. Отметь чекбоксы раздела в tasks.md, добавь запись в handoff.md (формат в начале файла) и сделай один коммит «feat(frontend): раздел 1 — каркас и сборка».

ОСОБЕННОСТИ РАЗДЕЛА
- Папка frontend/ уже существует (scripts/dev_snapshot.py). Не запускай интерактивный `npm create vite` прямо в неё: создай файлы вручную или сгенерируй шаблон во временной папке и перенеси. dev_snapshot.py не удалять.
- dev:mock без cross-env: `vite --mode mock` и файл .env.mock с VITE_API_MOCK=1.
- Mantine: подключи @mantine/core/styles.css и @mantine/dates/styles.css. MantineProvider — светлая схема по умолчанию, выбор хранится в localStorage (через try/catch). DatesProvider — локаль ru (dayjs/locale/ru).
- Mock-адаптер содержит уникальную строку-маркер (например, __TRAM_API_MOCK__), а скрипт проверки сборки падает, если маркер попал в static/index.html. Подключение mock только под import.meta.env.VITE_API_MOCK === '1'.
- Скрипт проверки сборки: абсолютные ссылки http(s) в <a href> допустимы, относительные src/href на файлы — нет.
- В index.html: <html lang="ru">, <title>Прогноз пассажиропотока трамваев</title>, meta viewport.
- Проверка поставки: после npm run build и перезапуска бекенда `curl http://127.0.0.1:8000/` возвращает новую страницу (title), в сетевой панели браузера нет 404.

ГОТОВО, КОГДА все пункты 1.1–1.6 выполнены и проверены, чекбоксы отмечены, handoff.md дополнен, коммит сделан. В конце кратко отчитайся: что сделано, что проверено, отклонения.
```

```text
- Окраска: одна GeoJSON-линия на маршрут со свойством route. Цвет и толщина — выражения ['match', ['get','route'], …], которые пересчитываются при смене часа или сценария через setPaintProperty. Новых запросов и перерисовки React-дерева на каждый час нет, держи ссылки на map в ref.
- Квантили классов считай по тем же значениям, что показываешь: для «Дня» — 24 × R значений этого дня; для периода — 24 × R средних по часу суток. Граница легенды — в посадках в час, целыми.
- Проигрывание: 0,8 с на час, по кругу, пауза. Таймер очищается при размонтировании. Если вкладка браузера скрыта — пауза.

Поиск остановки — Combobox с нормализацией названий (раздел 4). Карта с клавиатуры плохо доступна, поэтому поиск — основной доступный путь выбора.
- Участок: две остановки → пересечение наборов маршрутов. Проверь на «Метро "Семёновская"» + «Улица Ибрагимова» → 11 и 12.
- Запросов с stop_id быть не должно: проверь по сетевой панели.
```
