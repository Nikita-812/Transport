## Context

Мотивация — в proposal.md. Здесь только то, что определяет подход.

Бекенд (`forecast_api.py`, FastAPI) при старте загружает неизменяемый снимок прогноза и отдаёт его. Решение команды: в этом change бекенд, `Dockerfile`, `compose.yaml` и Python-тесты не меняются. Фронтенд опирается на наблюдаемое поведение:

- `GET /` отдаёт единственный файл `static/index.html` через `FileResponse`. Другой статики сервис не раздаёт, CORS не настроен.
- Снимок бывает двухмесячным (2025-11-01…2025-12-31) или годовым (2025-11-01…2026-10-31). Покрытие известно только из `/health`.
- Серверный `group_by` суммирует все выбранные маршруты в одну строку. Диапазона часов нет, а запрос с `stop_id` всегда возвращает 422.
- `/reference-map` содержит остановки только маршрутов 1, 5, 7, 11, 12 из справочника организаторов. Для 17, 25, 26, 28, 50 геометрии нет.
- Замер на годовом снимке (Windows, loopback): сырой год одного маршрута — 0,51–0,65 МБ JSON за 40–60 мс. `/reference-map` весит 41 КБ.

Проверено 2026-09-27 с машины команды в РФ:
- доступны `tile.openstreetmap.org`, `basemaps.cartocdn.com`, `tiles.openfreemap.org`;
- `overpass-api.de` отвечал 504, а зеркало `maps.mail.ru/osm/tools/overpass` работало;
- в OSM есть все 10 маршрутов, по одному relation (PTv2) на направление;
- остановки справочника совпадают с остановками OSM: медиана 9 м, p90 20 м (маршрут 7);
- при кластеризации до 60 м реальные общие остановки есть у маршрутов 11 и 12 (27 шт., например «Метро „Семёновская“»), 7 и 50 («Метро „Комсомольская“»), 11, 17 и 25 («Усадьба Останкино»), 5 и 50, 7 и 11, 11 и 25, 5 и 7, 12 и 50.

## Контракт API (наблюдаемый, не меняется)

| Запрос | Ответ |
|---|---|
| `GET /health` | `{"ready": true, "forecast_version": "pooled_route_blend:1ad02854ca82", "quality_passed": false, "serving_mode": "diagnostic", "coverage": {"start": "2025-11-01", "end": "2026-10-31"}}`; `serving_mode` — `production` или `diagnostic` |
| `GET /forecasts?route=17&start_date=2025-11-03&end_date=2025-11-03` | `{"forecast_version": "…", "routes": [17], "group_by": "raw", "rows": [{"route": 17, "date": "2025-11-03", "hour": 0, "prediction": 108.58}, …]}` — порядок: маршрут, дата, час; `prediction` — float ≥ 0 |
| `GET /forecasts?routes=1,17&…&group_by=weekday` | `rows: [{"weekday": "0", "prediction": 258093.26}, …]` — сумма по всем выбранным маршрутам |
| `GET /forecasts/export.csv?<те же параметры>` | CSV `;`, UTF-8, `Content-Disposition: attachment; filename=forecasts.csv` |
| `GET /forecasts.csv` | полный прогноз submission 2025-11-01…2025-12-31, `route;date;hour;prediction` |
| `GET /reference-map` | `{"schema_version": 1, "forecast_available": false, "note": "…", "routes": [{"route": 1, "trips": [{"trip_id": "2040920", "direction": "0", "stops": [{"stop_id": "2594", "name": "Чертаново Южное", "lat": 55.5946, "lon": 37.5908, "sequence": 1}, …]}]}]}`; без справочника — `{"forecast_available": false, "routes": []}` |

Параметры `/forecasts`:
- `routes` (через запятую) или `route`;
- `start_date` и `end_date` — обязательны, ISO, включительно, в пределах покрытия;
- `hour` — от 0 до 23;
- `group_by` — `raw` (по умолчанию), `hour`, `day`, `week`, `month`, `weekday`, `season`.

Ключи агрегатов: `hour` → `"08:00"`, `day` → ISO-дата, `week` → `"2025-W45"`, `month` → `"2025-11"`, `weekday` → `"0"`…`"6"` (пн = 0), `season` → `winter`/`spring`/`summer`/`autumn`.

Ошибки приходят с HTTP 422. Поле `detail` бывает строкой:
- `"routes contains an unsupported route"`
- `"routes must be comma-separated route numbers"`
- `"date range is outside the forecast snapshot coverage"`
- `"hour must be between 0 and 23"`
- `"unsupported group_by"`
- `"route or routes is required"`
- `"stop forecasts are unavailable: reference stops have no boarding target"`

Или списком ошибок валидации FastAPI: `[{"type", "loc", "msg", "input"}]`.

## Goals / Non-Goals

**Goals:**
- Дашборд работает поверх неизменённого сервиса одним файлом и проходит сценарии specs на годовом и двухмесячном снимках.
- Все представления согласованы: одни почасовые данные, один сценарий, одни фильтры.
- Каждый раздел tasks.md оставляет рабочий `static/index.html`. Этапы выполняют разные агенты: Codex и Claude Code.

**Non-Goals:**
- Изменения API, прогноз по остановкам, серверные сценарии, аутентификация.
- XLSX (CSV покрывает требование выгрузки), офлайн-тайлы, мобильное приложение.
- Реальные данные погоды и событий: только сценарные коэффициенты.

## Decisions

### D1. Стек

Выбран стек:
- Vite + React 19 + TypeScript в режиме `strict`;
- Mantine 8 (`@mantine/core`, `@mantine/dates`, `@mantine/hooks`) с dayjs и локалью `ru`;
- TanStack Query 5, Zustand;
- ECharts с модульным импортом `echarts/core`;
- MapLibre GL JS;
- Vitest, Testing Library, jsdom, ESLint.

Для ECharts и MapLibre пишем собственные тонкие обёртки: `useRef` + эффект, resize, dispose. `echarts-for-react` и `react-map-gl` не используются: меньше зависимостей и рисков совместимости с React 19, полный контроль над обновлением слоёв.

Версии — последние стабильные на момент установки, их фиксирует `package-lock.json`. Node 24.

Альтернативы:
- доработать vanilla-страницу — не масштабируется до карты и сценариев;
- Leaflet — слабее для стилизации линий по данным и анимации;
- Recharts — медленнее на рядах из тысяч точек.

### D2. Поставка одним файлом

`vite-plugin-singlefile` встраивает весь JS и CSS в `frontend/dist/index.html`. `npm run build` копирует его в `static/index.html` и запускает `scripts/verify_single_file.mjs`. Скрипт падает, если:
- есть ссылки `src=`/`href=` на относительные пути, кроме `data:`;
- размер больше 3,5 МБ;
- в файл попал маркер mock-режима.

`static/index.html` — артефакт сборки: он коммитится и руками не редактируется. Каждый раздел, меняющий UI, заканчивается пересборкой. Воркер MapLibre входит в её бандл (blob); если в собранной странице он не стартует, URL воркера задаётся через blob явно. Шрифты системные.

Альтернативы — Node-стадия в Dockerfile или отдельный nginx-контейнер — отклонены: обе требуют правок инфраструктуры бекенда.

### D3. Среда разработки

Разработка идёт против настоящего бекенда. `frontend/scripts/dev_snapshot.py` обучает принятую модель `pooled_route_blend` и записывает годовой снимок со справочной картой в `artifacts/service`. Папка в `.gitignore`, код бекенда скрипт не меняет. Флаг `--horizon submission` даёт двухмесячный снимок для проверки того, как ведут себя «Год» и «Сейчас».

Снимок пишется плоско — `forecast.csv`, `metadata.json`, `reference_map.json` — без `forecast_export.publish_snapshot`. Причина:
- на Windows Python создаёт каталоги `tempfile` с доступом только для владельца;
- Codex выполняет команды от отдельного пользователя песочницы (`CodexSandboxUsers`).

Поэтому всё, что Python провёл через временный каталог (`publish_snapshot`, `pipeline prepare`), читает только создавший это агент. Обычные файлы наследуют права рабочей папки и доступны обоим.

Скрипт отказывается перезаписывать снимок, созданный не им: указатель `current` или `metadata.json` без его метки.

Если `data/processed/history.csv` не читается, потому что его создал другой агент:

```
.venv/Scripts/python.exe -m pipeline prepare --archive dataset --output-dir <папка>
.venv/Scripts/python.exe frontend/scripts/dev_snapshot.py --data-dir <папка>
```

Запуск бекенда: `FORECAST_DIR=artifacts/service .venv/Scripts/python.exe -m uvicorn forecast_api:app --port 8000`.

Vite dev-server проксирует `/health`, `/forecasts*` и `/reference-map` на `http://127.0.0.1:8000`.

Для сред без данных (облачный агент, CI) есть mock-адаптер: `VITE_API_MOCK=1`, `npm run dev:mock`. Он отдаёт детерминированные синтетические данные тех же форм: годовое покрытие, профиль будни/выходные с пиками в 8 и 18 ч, мини-справочник, те же ошибки. В production-сборку адаптер не попадает — его отсекает условие на `import.meta.env`, а сборка проверяет отсутствие маркера.

### D4. Доступ к данным и модель в памяти

Для каждого выбранного маршрута отправляется свой запрос `GET /forecasts?route=R&start_date=S&end_date=E` (raw) на видимый диапазон, все параллельно. Кэш TanStack Query:
- ключ `[forecast_version, route, S, E]`;
- `staleTime: Infinity`, потому что снимок неизменяем, а версия входит в ключ;
- устаревшие запросы отменяются.

Ответ нормализуется в `RouteSeries { route, start, days, values: Float64Array(days × 24) }` с индексом `dayIndex × 24 + hour`. Агрегации, сценарии, остановки, выпуск и CSV считаются на клиенте чистыми функциями в `src/domain/*`.

Почему так:
- серверный `group_by` сливает маршруты;
- у сервера нет диапазона часов;
- сценарии применяются к почасовым значениям.

Год по 10 маршрутам — около 5,8 МБ JSON и 87 600 значений. Локально это приемлемо, а проход по `Float64Array` занимает миллисекунды. Серверные агрегаты используются только в ссылке «Базовый прогноз (API)» и в тесте согласованности.

Альтернативы:
- серверный `group_by` по одному запросу на маршрут — нет диапазона часов, нельзя применить почасовые правила;
- весь снимок одним запросом — 5,8 МБ даже для дневного вида.

### D5. Время и горизонты

Даты хранятся как строки `YYYY-MM-DD`. Арифметика идёт в UTC-полночь, без `new Date('YYYY-MM-DD')` в локальном поясе. «Сегодня» и «текущий час» берутся из `Intl.DateTimeFormat` с `timeZone: 'Europe/Moscow'`.

Горизонты повторяют `forecast_export.horizon_end`:
- день — дата начала;
- месяц — начало + 1 месяц − 1 день, число ограничивается длиной месяца;
- год — начало + 1 год − 1 день;
- период — произвольный диапазон.

Всё обрезается покрытием из `/health` с видимой пометкой.

Детализация по умолчанию: день → час, месяц → день, год → неделя. Для периода: до 2 дней → час, до 92 дней → день, иначе неделя.

### D6. Семантика агрегатов

Как у бекенда:
- значение корзины — сумма посадок;
- неделя по ISO (`2025-W45`);
- день недели: понедельник = 0;
- сезоны: декабрь–февраль — зима, март–май — весна, июнь–август — лето, сентябрь–ноябрь — осень.

Профили «час суток» и «день недели» — среднее за день: сумма, делённая на число дней с этим часом или днём недели в диапазоне. Подпись: «в среднем за день».

KPI:
- итог;
- пиковый час по суммарному ряду выбранных маршрутов;
- самый загруженный маршрут;
- среднее за час.

На экране — целые числа в формате `ru-RU`. Расчёты идут без округления.

### D7. Модель сценария

Правило:

```ts
{ id, kind: 'weather' | 'season' | 'event', name, multiplier,
  routes: 'all' | number[], dates: null | { from, to },
  hours: null | { from, to }, season?: 'winter' | 'spring' | 'summer' | 'autumn', enabled }
```

Коэффициент часа маршрута — произведение множителей всех подходящих включённых правил, ограниченное диапазоном [0; 3]. Итог = база × коэффициент. Сценарий применяется к почасовым значениям до агрегации одной функцией `applyScenario(series, rules)`, поэтому все представления согласованы.

Пресеты погоды:
- Ясно — 1,00;
- Дождь — 0,95;
- Снегопад — 0,92;
- Сильный мороз (ниже −20 °C) — 0,90;
- Жара (выше +30 °C) — 0,95.

Пресеты событий: «Матч или концерт» — 1,30, «Городской праздник» — 1,20, «Ремонт или перекрытие» — 0,50.

Все пресеты — экспертные допущения, и их можно править. Сценарий хранится в `localStorage` под версионированным ключом, все обращения обёрнуты в `try/catch`.

### D8. Карта

MapLibre GL JS.

**Подложка.** Растровые тайлы, источники по порядку:
1. OSM `https://tile.openstreetmap.org/{z}/{x}/{y}.png`;
2. CARTO `https://basemaps.cartocdn.com/{light_all|dark_all}/{z}/{x}/{y}.png`.

При серии ошибок тайлов карта переключается на следующий источник. Если все недоступны — нейтральный фон с пометкой. Атрибуция обязательна. Тёмная тема — CARTO `dark_all` или приглушённый растр (`raster-saturation`, `raster-brightness-max`).

**Линии.** OSM-геометрия путей для всех 10 маршрутов. Справочник организаторов даёт только точки остановок, и прямые отрезки между ними на подложке режут кварталы. Если OSM-линии у маршрута нет, запасной вариант — ломаная по упорядоченным остановкам справочника.

**Остановки.** Для 1, 5, 7, 11, 12 — справочник организаторов (`/reference-map`), для 17, 25, 26, 28, 50 — OSM. Индекс остановок:
- точки обоих источников кластеризуются по расстоянию до 60 м (гаверсинус);
- имя кластера берётся из справочника, иначе самое частое из OSM;
- набор маршрутов кластера — объединение маршрутов его точек.

**Нагрузка.** Значение маршрута для выбранного часа после сценария: на горизонте «День» — прогноз этой даты, на многодневном периоде — среднее за день для этого часа. Окраска:
- 5 классов по квантилям всех значений «маршрут × час» выбранных маршрутов за период;
- последовательная палитра, различимая для дальтоников, одинаковая в обеих темах;
- толщина 2–10 px, пропорциональна √значения.

Смена часа меняет только paint-выражения (`setPaintProperty` или feature-state), данные не перезагружаются. Проигрывание — 0,8 с на час, по кругу.

**Участок** — две выбранные остановки, маршруты берутся пересечением их наборов.

### D9. Геометрия OSM

`frontend/scripts/fetch_osm_routes.mjs` — Node без зависимостей.

Зеркала Overpass по очереди:
1. `https://maps.mail.ru/osm/tools/overpass/api/interpreter`
2. `https://overpass-api.de/api/interpreter`
3. `https://overpass.kumi.systems/api/interpreter`

Каждый запрос — с `User-Agent` проекта и таймаутом.

Запросы:
1. `relation["type"="route"]["route"="tram"]["ref"~"^(1|5|7|11|12|17|25|26|28|50)$"](55.49,37.30,56.00,37.97);out geom;` — теги и геометрия членов (bbox Москвы; фильтр по имени области ломается на кодировках);
2. `rel(id:…)->.r;node(r.r);out;` — теги узлов-остановок: роли `stop`, `stop_entry_only`, `stop_exit_only`, для имени — `platform*`.

Обработка:
- пути relation с пустой ролью склеиваются в последовательные отрезки (MultiLineString);
- упрощение Дугласом — Пекером с допуском 5 м;
- координаты округляются до 5 знаков;
- остановки по relation-направлениям дедуплицируются.

Выход — `frontend/src/data/osm-routes.json`:

```json
{ "source": "OpenStreetMap via Overpass API", "license": "ODbL 1.0",
  "attribution": "© OpenStreetMap contributors", "fetched_at": "…", "endpoint": "…",
  "routes": [{ "route": 17, "relations": [{ "id": 540033, "name": "…", "from": "…", "to": "…" }],
               "lines": [[[37.6, 55.8], …]], "stops": [{ "id": "node/…", "name": "…", "lat": 55.8, "lon": 37.6 }] }] }
```

Ожидаемый размер — 100–250 КБ, сырой ответ весит около 0,9 МБ. Файл коммитится и вшивается в сборку. Скрипт нужен только для обновления и при полной неудаче не портит существующий файл.

### D10. Графики

ECharts с модульным импортом: серии line, bar, heatmap; компоненты grid, tooltip, legend, dataZoom, markArea, visualMap.

- Палитра 10 маршрутов постоянная — одна для чипов, графиков и таблицы — и различимая для дальтоников. Тема графиков следует теме приложения.
- Праздники, переносы и предпраздничные дни берутся из `src/data/calendar.ts`. Он скопирован из `calendar_2025.json` и `calendar_2026.json` вместе с источниками.
- Для рядов длиннее 60 точек включается `dataZoom`.
- Сценарий рисуется пунктиром поверх сплошной базы.

### D11. Состояние

Zustand-стор хранит фильтры, сценарий и UI: вкладку, выбранную остановку или участок, час карты, режим «Сейчас».

Фильтры и вкладка синхронизируются с query string:

```
?routes=1,17&h=month&start=2025-11-01&end=2025-11-30&hours=7-10&g=day&tab=map
```

Некорректные параметры URL игнорируются, пользователь получает уведомление. Сценарий и допущения выпуска хранятся в `localStorage`.

### D12. Ошибки

`src/api/errors.ts` превращает ошибки в русские сообщения:
- известные строки `detail` — в готовые тексты;
- списочный `detail` — по `loc` и `type` (например, «Некорректная дата начала»);
- сеть и ответы 5xx — «Сервис прогнозов недоступен», с повтором;
- всё остальное — общее сообщение с раскрываемыми техническими деталями.

Клиентская проверка ввода не пропускает заведомо неверные запросы.

### D13. Статус снимка и сведения о модели

Название модели — префикс `forecast_version` до `:`. `src/data/model-info.ts` содержит только факты из раздела «Факты для вкладки „О модели“»; для неизвестной модели показывается одна версия.

`serving_mode: diagnostic` показывается нейтральным бейджем «Диагностический снимок» с пояснением: внутренний порог команды — WAPE-score ≥ 0,95 на каждом срезе, это строже шкалы жюри, где максимальный балл дают за > 0,88.

### D14. Проверки и бюджеты

**Тесты Vitest:**
- доменные функции на ручных примерах: горизонты, агрегаты, сценарии, остановки, выпуск, CSV, ошибки;
- компонентные тесты ключевых потоков с подменой `fetch`;
- тест согласованности клиентских агрегатов с семантикой серверного `group_by` на фикстуре.

**В конце каждого раздела:**
- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`;
- `.venv/Scripts/python.exe -m unittest discover` остаётся зелёным. Системный `python` на машине команды без зависимостей бекенда даёт ложные ошибки;
- проверка в браузере против бекенда со снимком разработки.

**Бюджеты:**

## Факты для вкладки «О модели»

Интерфейс показывает только эти факты. Источник — README и `accuracy.py` в ветке `main` на 2026-09-27.

**`pooled_route_blend`** — принятая модель.
- Устройство: среднее 50/50 общей модели HistGradientBoosting по всем маршрутам и отдельных моделей для каждого маршрута.
- Параметры: loss absolute_error, глубина 8, learning rate 0,1, 300 итераций, random_state 42.
- Признаки: маршрут, час, день недели, месяц, выходной, праздник, рабочий день с учётом переносов, предпраздничный день, число дней от 01.01.2025 (тренд).
- Обучение на январе–октябре 2025. Прогноз не обновляется внутри горизонта.
- WAPE-score при прогнозах, округлённых до целых, и обучении только на прошлом: май–июнь 0,861; июль–август 0,835; сентябрь–октябрь 0,840 (этот срез изучался в EDA и не независим); ранние срезы вместе 0,848.

**`hist_absolute_error_depth_8_lr_0.1_iter_300`** — прежний frozen winner, одна общая модель HistGradientBoosting с теми же признаками.
- WAPE-score: май–июнь 0,857; июль–август 0,827; вместе 0,843.

**Качество и шкала:**
- WAPE = Σ|y − ŷ| / Σy; WAPE-score = max(0, 1 − WAPE).
- Baseline организаторов на скрытом периоде (ноябрь–декабрь 2025) ≈ 0,48.
- Официальная оценка нашего прогноза на скрытом периоде команде неизвестна.

**Область определения:**
- маршруты 1, 5, 7, 11, 12, 17, 25, 26, 28, 50; уровень «маршрут × час»;
- проверены горизонты до двух месяцев;
- год — качественная оценка: ноябрь и декабрь не встречались в обучении; признак тренда за пределами обучения не растёт, деревья продлевают уровень конца октября 2025;
- маршрут 5 редок в данных.

**Область адаптации:**
- новый маршрут — история валидаций за несколько месяцев и переобучение;
- новый год — производственный календарь;
- прогноз по остановкам — привязка валидаций к остановкам (телематика, GPS, расписание);
- погода — исторический источник погоды, переобучение и проверка эффекта;
- события — календарь событий с историей.

**Источники:**
- датасет хакатона — https://disk.yandex.ru/d/DiFwlfMOauxjBg (валидации, labels, справочник остановок);
- производственный календарь 2025 — постановление Правительства РФ от 04.10.2024 № 1335, https://government.ru/docs/all/155500/;
- производственный календарь 2026 — постановление от 24.09.2025 № 1466, https://government.ru/docs/all/161028/;
- ТК РФ, статьи 95 и 112 — https://pravo.gov.ru/proxy/ips/?docbody=&nd=102074279;
- OpenStreetMap (пути и остановки маршрутов 17, 25, 26, 28, 50) — https://www.openstreetmap.org/copyright, ODbL, получено через Overpass API (зеркало https://maps.mail.ru/osm/tools/overpass/);
- тайлы OSM — https://operations.osmfoundation.org/policies/tiles/;
- CARTO basemaps — https://carto.com/attributions.

**Ограничения:**
- нет прогноза по остановкам: сумма маршрутов — не посадки на остановке;
- погода и события — только сценарные допущения;
- годовой горизонт не валидирован;
- снимок диагностический по внутреннему порогу команды;
- геометрия OSM актуальна на дату выгрузки.

**План развития:**
- привязка валидаций к остановкам по телематике;
- источник погоды с проверкой эффекта;
- события и перекрытия;
- регулярное переобучение;
- серверные сценарии в API.

## Risks / Trade-offs

- [`static/index.html` расходится с исходниками] → меняется только через `npm run build`; пересборка в конце каждого раздела; размер и хеш сборки пишутся в `handoff.md`.
- [Тайлы недоступны у жюри] → цепочка источников и режим без подложки; остальные функции от внешней сети не зависят.
- [Год × 10 маршрутов нагружает браузер] → `Float64Array`, мемоизация, запрос только видимого диапазона; замер в разделе 8.
- [Бекенд поставит двухмесячный снимок] → «Год» обрезается с пояснением, «Сейчас» открывает начало покрытия; проверяется на `dev_snapshot.py --horizon submission`.
- [Overpass недоступен при обновлении] → зеркала; файл уже закоммичен; для 1, 5, 7, 11, 12 есть запасные линии из справочника.
- [Сумму маршрутов примут за посадки на остановке] → обязательная подпись в панели остановки и в «О модели».
- [Коэффициенты примут за обученную погоду] → пометка «допущение» у пресетов и в «О модели».
- [Два агента правят одно и то же] → строго последовательные разделы, `handoff.md`, один коммит на раздел.
- [Вывод Python через `tempfile` одного агента недоступен другому (ACL только для владельца)] → снимок разработки пишется плоско. При недоступности `data/processed` — пересборка в свою папку и `--data-dir` (D3). Права файлов не менять.
